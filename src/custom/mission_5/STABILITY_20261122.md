# Mission 5 파지 안정화 — 2026-11-22

기준: main `5bfd039`. 최종 제어·인식 커밋: `14cee36`. 파지 제어와 인식 편향을 분리해 개선하고, 중간 후보의 회귀·실패도 보존했다.

**최종 결과: 동일 배치 기존 4/8 → 개선 8/8 PASS, 별도 새 배치 12/12 PASS.** 최종 본시험 20개 고유 배치에서 모두 공식 PASS였고, 앞선 회귀 배치 1개도 별도로 복구를 확인했다. 개발 8개와 독립 평가 12개를 구분하며 20개 전부를 독립 평가로 세지 않는다. 새 배치의 공식 실행 시간은 평균 33.85초(29.87–35.64초)였다.

## 문제와 원인

기존 정책을 공식 랜덤 샘플러의 고정 seed `8122` 배치 8개에서 실행하니 4개만 공식 PASS였다. 실패 중 2개는 `close` 단계의 12초 시간 초과, 2개는 동작을 완주했지만 연필이 입구 밖에 놓인 경우였다. 종료 상태만으로 삽입 성공을 세지 않았다.

학습된 close 목표는 descend 목표보다 약 5.65mm 낮고 옆으로 약 4mm 이동한다. 이 수치는 시연에서 관측된 접촉 후 변위까지 endpoint로 학습한 것이다. 이미 물체를 잡아 손가락 폭이 안정된 뒤에도 일반 pose servo가 이 목표를 맞추려 했다. 연필–책상 접촉·마찰로 이동이 제한되면 6mm 위치 허용치를 통과하지 못하거나, 닫힌 손으로 연필을 밀어 이후 lift 중 상대 회전을 유발할 수 있다. 단순히 timeout을 늘리는 해결책은 채택하지 않았다.

실제 시간 초과의 마지막 관측값(target−measured, Panda-base):

| 개발 case | 위치 오차 XYZ (mm) | 거리 | 각도 오차 | 마지막 3.5초 손가락 총간격 |
|---|---|---:|---:|---:|
| 005 | `[5.077, 4.064, -1.772]` | 6.740mm | 0.00114rad | 29.252 ± 0.004mm |
| 006 | `[-1.120, 12.609, -6.394]` | 14.182mm | 0.00258rad | 27.572 ± 0.012mm |

두 경우 모두 각도는 0.08rad 조건을 충분히 통과하지만 위치만 6mm 조건 밖이었다. 005는 공식 평가에서도 실제 파지가 유지됐고, 006은 폭이 안정적이어도 실제 파지는 실패했다. **손가락 간격은 보조 증거이며 파지 정답 판정기가 아니다.** 손가락 자체가 책상에 직접 충돌했다고 단정할 근거는 없다.

## 수정

- 학습된 open→closed 전환에서 도착 시점의 측정 EE pose를 한 번 저장해 유지한다. 닫는 중 접촉 변위를 다시 강제하지 않는다. 학습된 접근·운반·삽입 목표, grip, dwell과 checkpoint를 보존한다.
- 최소 학습 dwell에 더해 손가락 총간격 8–65mm, 연속 간격 변화 1mm 이하가 0.3초 이상 유지되고, 팔 위치·각도 drift도 기존 허용치 안에 있을 때 다음 학습 단계로 간다. 빈 파지·넓게 열린 손·계속 움직이는 팔/손가락은 성공 전환으로 세지 않는다. 단계 timeout은 유지했다.
- HSV Hue 하한을 20→18로 넓혀 조명 때문에 누락되던 노란 몸통을 포함한다. 같은 component의 기존 H20 픽셀 PCA 방향에 새 축의 부호를 정렬해, 단순 threshold 변경으로 파지 방향이 180° 바뀌는 회귀를 막는다. 보이는 eraser의 방향 보정은 기존처럼 우선한다. 카메라 보정은 변경하지 않았다.
- PCA 선축의 `θ`와 `θ+π`를 첫 관측 분기에 맞춰 평균한다. 서로 반대인 축이 상쇄되는 경우를 막고 방향 불안정은 거부한다. 실제 연필 팁 방향을 완전히 판별하는 기능은 아니다.
- 실패 시 마지막 stage·센서 상태·오차를 결과와 선택적 trace에 남긴다.
- `benchmark.py`는 공식 `randomize_panda_task` 분포를 seed별로 샘플링하고 원본 main의 `--scenario`로 각 배치를 실행한다. 평가기만 시나리오를 만들고 읽으며 정책에는 전달하지 않는다. 자체 GPU lock을 사용한다.

## 1차 후보와 회귀 발견

|---|---:|---:|---:|
| 기존 main `5bfd039` | 4/8 | 2 | 2 |
| 개선 `37449eb` | 8/8 | 0 | 0 |

index·case seed·시나리오 SHA256을 모두 대조했다. 기존 성공 4개를 유지하고 실패 4개를 모두 개선했다. 원본 시뮬레이터와 referee를 그대로 사용했다. 배치 재현이며 ROS 스케줄링·물리 궤적까지 비트 단위로 동일한 시험은 아니다.

case 000은 같은 학습 목표에서도 결과가 달라졌다. close가 약 7.5→1.0초(sim trace)로 줄고, 연필축–EEF Y축의 사후 영상 근사 각도가 lift 끝 71.3→0.9°, carry 끝 80.3→0.6°로 개선됐다. 기존에는 연필이 lift 중 손에 대해 회전했고, 개선안은 삽입 직전까지 자세를 유지했다. 각도는 두 RGB·자기 상태·공개 카메라 보정으로 복원한 근삿값이다. 공식 실행 시간은 38.27→37.24초로, sim trace 차이를 그대로 벽시계 단축으로 보고하지 않는다.

## 별도 새 배치 평가

seed `221122`, 새 12개 배치에서 1차 후보는 **10/12 PASS**였다. 이 결과를 본 뒤 기존 정책으로 같은 배치의 대조를 시작했고, case 000에서 기존 PASS/후보 FAIL 회귀를 확인했다. 1차 후보는 main에 반영하지 않았다. 기존 대조는 완료 case 0–2와 중단 case 3으로 남겼고, 중단 실행은 성능 분모에서 제외한다. 이 seed는 이후 보완에 사용했으므로 최종안의 독립 평가 세트로 부르지 않는다.

새 배치에서 드러난 별도 한계:

- case 000은 파지·운반 중 연필 정렬을 유지했지만, 공식 판정에서 깊이 10.8mm(요구 20mm)이고 로봇 접촉이 남았다. 손가락은 열렸으므로 '열기 명령 발행'과 실제 해제를 구분해야 한다. 두 RGB 분석은 중심에서 약 12mm 촉 쪽 파지와 해제 후 접촉 잔류를 시사한다. H20/H18 중심 차이 약 19mm와 높은 도착 pose를 유지하는 trade-off가 있어 색 인식만을 단독 원인으로 확정하지 않았다.
- case 002는 `carry`의 위치 약 13.46mm·각도 0.140rad 오차가 남아 시간 초과했다. 파지 확인 조건을 완화해 이 문제를 숨기지 않았다. 먼 배치의 waypoint 도달성과 학습 시연 범위가 다음 개선 대상이다.

1차 후보의 12개 평가 중에는 정책을 변경하지 않았다. 이후 이 반례를 개발 사례로 사용했으므로 최종안의 독립 평가로 재사용하지 않는다. 파지 안정화가 전체 미션의 모든 실패를 해결했다는 주장도 하지 않는다.

후속으로 손을 연 채 학습 close pose에 먼저 정렬하는 후보도 시험했으나 회귀 case 000에서 0/1 FAIL로 선택하지 않았다. 최종 후보는 파지 중 hold를 유지하면서, 영상에서 확인한 몸통 중심 편향을 따로 줄이는 방식이다. 따라서 위 1차 후보 수치를 최종 후보 성능으로 재사용하지 않는다.

## 최종 후보 검증

최종안은 파지 중 hold와 H18 몸통 검출/H20 방향 보존을 함께 사용한다. 기존 회귀 case `221122/0`에서 공식 PASS를 확인했고, 제어·인식 코드를 고정했다. 이후 비교 seed `8122`의 8개에서 **8/8 PASS**, 사전에 지정한 새 seed `221123`의 12개에서 **12/12 PASS**였다. 기존 성공 4개를 유지하고 기존 실패 4개를 모두 개선했다.

새 seed는 첫 1차 후보 평가와 다른 seed다. `v3_evaluation_plan.json`에 12개 index를 사전 기록했고, 결과를 보고 좋은 배치만 선택하지 않는다. 개발 배치와 독립 평가 결과를 구분한다.

새 12개 표본은 Panda base로부터 연필 반경 약 0.376–0.636m, 꽂이 반경 0.382–0.623m, 연필 yaw 약 −29.37–29.86°, 꽂이 yaw −13.16–12.12°, 물체 간 거리 0.263–0.431m를 포함했다. 이는 실제 표본 범위이며 공식 분포 전체를 덮었다는 뜻은 아니다. 양쪽 모두 성공한 개발 4개 평균 공식 시간은 기존 34.19→최종 34.73초여서 속도 향상을 주장하지 않는다.

최종 미션 5 회귀 검사 47개(기존 35 + 접촉 파지·빈 손·팔 drift·손가락 안정성·PCA 축 검사 7개 + 인식 검사 5개), 공통 검사 46개를 별도 `haic_rai301_verify` 환경에서 통과했다. `pip check`도 통과했다. 인식 검사는 H19 몸통 복원·PCA 부호·29/30 기준 경계·분리 잡음·eraser 보정의 회귀를 다룬다. 저장 RGB 28장에서도 최대 방향 변화는 약 0.813°, 180° 반전은 0건이었다. 단위 검사·offline replay는 실제 공식 PASS를 대신하지 않는다.

본시험은 고정 카메라·기본 방 배치에서 공식 분포의 물체 배치만 바꾼 시험이다. 작은 표본의 12/12가 임의 조명·모든 방 재배치·연속 미션 조건에서 100% 성공을 보장하지 않는다. 연필 미끄러짐의 실시간 직접 추적과 먼 waypoint 도달성은 추가 개선 여지가 있다.

## 재현과 증거

저장소 `src/`, 대회 Conda 환경에서:

```bash
# 다른 시뮬레이터를 시작하지 않는다. 이 도구가 자체 GPU lock을 잡는다.
python -m custom.mission_5.benchmark --seed 8122 --cases 8 --out ~/m5-runs/recheck-development
python -m custom.mission_5.benchmark --seed 221123 --cases 12 --out ~/m5-runs/recheck-unseen
# 특정 배치 하나만 다시 실행
python -m custom.mission_5.benchmark --seed 8122 --case-index 5 --out ~/m5-runs/recheck-case5
```

출력 폴더는 새 경로를 지정한다. 각 case에 `scenario.yaml`, `main.log`, `official_result.json`, `result.json`, 두 카메라와 자기 상태 trace가 저장된다. `result.json`에는 소스·모델 해시와 실행 중 변경 여부도 있다. `/panda/retry`는 별도 난수기를 써 seed만으로 동일 배치 비교가 되지 않으므로 이 비교에 사용하지 않았다.

원본 큰 trace는 공유 노트북 `~/m5-runs/stability-20261122/`에 보존한다. Git에는 요약·공식 결과·필요한 분석 근거만 포함한다. 미션 1–4·6, 공유 센서 설정, 의존성과 조교 원본 코드는 변경하지 않았다. 초기 학습·CNN 비교 결과는 [이전 보고서](REPORT.md)에 보존했다.

작은 증거 묶음은 [docs/validation/stability_20261122](docs/validation/stability_20261122)에 있다. `analysis/v3_summary.json`과 `compare_v3.json`은 시나리오 SHA 일치, 개발/새 배치 중복 없음, 실행 중 코드·모델 동결, 사전 선언된 전체 index 완료를 확인한다. 중간 후보·중단 사례도 별도 이름으로 보존했다. 판정의 물체 상태는 평가 증거이며 제출 정책 입력으로 사용하지 않는다.
