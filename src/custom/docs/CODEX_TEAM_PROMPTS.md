# 팀원별 Codex 작업 프롬프트

각 파일은 공통 규칙이 포함된 독립 프롬프트다. 맨 위 `[INI]`를 본인 이니셜로 바꾸고 파일 전체를 SSH를 사용할 수 있는 Codex에 넣는다. 여러 파일의 공통 문구를 합칠 필요는 없다. 작성 시 확인한 main은 `e48a9a1`이며, 프롬프트는 작업 시작 때 최신 origin/main을 다시 확인하도록 한다.

| 담당 | 프롬프트 | 주된 목표 |
|---|---|---|
| 미션 1 / 공통 기반 | [01 미션 1·이동·플래너](prompts/01_mission1_navigation.txt) | 기존 성공 유지, 장거리 위치 추정·정체·공통 이동 개선 |
| 미션 2 | [02 색 콘 접근](prompts/02_mission2_cones.txt) | 세 색·배치·출발 위치에서 성공 유지와 시간 단축 |
| 미션 3 | [03 절벽 코스](prompts/03_mission3_cliffs.txt) | 바닥·가장자리 감지와 입구→출구 실제 통과 |
| 미션 4 | [04 방 인식·배달](prompts/04_mission4_rooms.txt) | 다른 방 순서에서도 VLM 분류, 교실 진입까지 성공 |
| 미션 5 | [05 학습 정책·파지 최적화](prompts/05_mission5_from_scratch.txt) | 학습 keypose 기준선 유지, 파지 안정성·배치 일반화 개선 |
| 미션 6 | [06 축구](prompts/06_mission6_soccer.txt) | 흰 골대/링 오검출 제거, 공 추적·이동·실제 득점 |

5명이라면 미션 1 담당이 공통 기반·통합을 맡고, 미션 2와 6을 한 담당자가 관리하는 구성이 공유 vision.py 충돌을 줄인다. 각자 별도 branch/worktree를 사용하고 공통 이동 코드는 한 담당자가 관리한다. 다른 배정이라면 미션 2의 cone()과 미션 6의 ball() 소유 범위를 지키고 공통 프레임 처리 변경을 조율한다.

프롬프트는 실제 시뮬레이터·학습의 공유 GPU 사용을 조율하고, 본인 opt 브랜치에 결과를 남기도록 작성했다. main 자동 병합은 지시하지 않는다. 2026-11-21 미션 5 구현 후 05번 출발점을 갱신했다. 실제 학습 keypose와 성공/실패 기록은 [미션 5 보고서](../mission_5/REPORT.md)를 기준으로 최적화한다.

시작 전 [검증 보고서](VALIDATION_REPORT.md), [협업 가이드](TEAM_OPTIMIZATION.md), [실행 README](../README.md)를 함께 확인한다. 임시 실험·개발 seed와 손대지 않은 평가 seed의 결과를 구분하고, 실제 공식 PASS와 코드·단위 검사 통과를 구분한다.
