### 대회 입력 모드

원본 `main.py --llm-web`과 실제 CPU Qwen1.5B를 실행했다. 테스트 도구가 웹 화면과 같은 request-file 프로토콜로 다음 문장을 전달했다. 브라우저 클릭 자체를 자동화한 검사는 아니다.

`Walk to (15.5, 18.0), then go to the green cone.`

시뮬레이터는 `--hide-targets`로 목표·색을 미션 API에서 숨겼다. LLM이 추출한 `goal`과 `color`가 `self.params`로 전달됐고 두 미션 모두 공식 PASS였다. 명령부터 최종 판정까지 65.8초. `web_smoke.json`의 state는 done이며, 검증 도구가 완료 뒤 상시 대기하는 웹 모드를 종료해 원본 run 결과에는 interrupted 표시가 남는다.

## 팀원 인수인계

공통 위치 추정·이동은 한 명이 관리한다. 미션 2 담당은 이미 PASS한 콘 접근의 다른 색·출발 위치·장시간 재현을 확대한다. 미션 3 담당은 전역 위치 추정·바닥 가장자리 감지·좁은 통로 제어를 개선한다. 미션 4 담당은 관측 자세와 VLM 정확도, 교실 진입을 검증한다. 미션 6 담당은 골대/링 오검출을 제거하고 관측 공을 유지한 채 밀기를 안정화한다. 미션 5는 기존 담당자가 독립적으로 계속 진행한다.

각자는 미션 브랜치에서 작업하고 실험 기록·seed·공식 판정 파일을 함께 남긴다. 단순 코드 복사 대신 diff를 검토해 통합하고, 공유 파일의 변경은 공통 기반 담당자와 조율한다.

## 최종 추가 기록

최종 미션 4는 seed417의 평가 시나리오에서 공식 방 판정 3/3, 배달 실패로 전체 FAIL(245.6초)이었다. 방 종류별 실제 영상 조건부 확률에 공개된 일대일 배치 조건을 적용했다. 독립 최상위 분류는 모두 medical이었으므로 개별 이미지 분류가 안정적이라고 주장하지 않는다. 이 seed의 방 순서는 우연히 기본 순서(classroom/medical/cafeteria)와 같았다. 다른 방 순서에서의 일반화는 확인하지 못했다.

미션 6 최종 추적 보정판도 실제 실행 FAIL(67.1초)이었다. 초기 공 관측이 흰 골대 표시를 공으로 오인해 다른 위치로 접근했고 실제 공은 움직이지 않았다. 따라서 공 검출 성공 사례가 있다는 사실을 득점 성공으로 표현하지 않는다.

대회 모드의 상태 파일과 문법 검사가 생성한 추적 캐시는 원복했다. 실행 증거는 `docs/validation/official/`에 보존한다. GitHub에는 코드·보고서·검증 JSON을 올리며, 큰 모델 가중치는 제외하고 버전을 고정한 다운로드 스크립트를 제공한다. Ubuntu 원본 custom/models에는 실제 가중치도 배치한다. 모델은 CPU로 실행하며 대회 환경 외의 Lab6 Conda 환경·학습 작업은 변경하지 않았다.
