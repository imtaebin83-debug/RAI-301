# 규칙 검토와 구현 근거

검토일: 2026-11-21 (Asia/Seoul)

## 검토 범위

`imtaebin83-debug/RAI-301`의 대회 `README.md`를 기준으로 환경 설치와 구현 계획을 검토했다. 아래 내용은 해당 README의 해석이며, 대회 전 최신 README와 조교 추가 공지의 변경 여부를 다시 확인해야 한다. 논문과 공식 프로젝트 중 이번 구현에 유용한 자료를 선별했으며, 관련 연구 전체를 조사했다는 뜻은 아니다.

초기 구현의 첫 성과는 기본 시나리오 미션 1 PASS(23.1초, 오차 약 0.06m)였다. 이후의 무작위 연속 실행·대회 입력 모드·다른 미션의 성공과 실패는 `VALIDATION_REPORT.md`와 공식 JSON에 정리했다. 본 문헌 검토를 성공률 측정으로 해석하지 않는다.

## README와 원본 API 사이의 위치 정보 불일치

원본 `process_mission_begin_requests`를 확인한 결과, `selected` 응답의 `pos`는 현재 G1 위치가 아니라 `mission_spawns[index]`에 저장된 미션별 연습 시작 위치이다. `begin_mission()`이 G1을 이동시키지 않는 동작과 함께 보면, 이 값을 매 미션의 실제 출발 위치로 사용한 추정기는 잘못된 월드 좌표에 고정된다. README의 상태 설명만으로 해당 응답을 실제 위치라고 판단하면 안 된다.

이를 해결하기 위해 bringup에서 연속 위치 추정 노드를 실행한다. 시뮬레이터 시작 때 README에 공개된 초기 자세 `(x=16, y=11, yaw=0°)`로 한 번만 월드 좌표를 정하고, 이후 미션 선택의 `selected` 위치는 무시한다. IMU와 LiDAR, 로봇 링크 TF를 이용해 이동을 계속 추정하며, 실제로 위치가 바뀌는 새 `respawned` 이벤트에서만 허용된 리스폰 자세로 재초기화한다. 평가에서 다른 시작 자세를 명시적으로 설정할 때는 그 공개된 초기 자세를 환경 변수로 함께 넘겨야 하며, 숨은 시뮬레이터 현재 위치를 읽어 보정하는 용도로 사용하면 안 된다.

초기 미션 2 실패 실행에는 잘못된 미션 시작 앵커가 사용되었다. 따라서 그 결과는 이 앵커 오류가 포함된 구현의 실패이며, 수정된 연속 위치 추정기를 사용한 미션 2의 성능과 구분해야 한다. 위에 적은 미션 1 기본 시나리오 PASS는 공개 시뮬레이터 시작 자세와 미션 1의 초기 앵커가 같아 이 불일치의 영향을 받지 않은 결과이다. 수정 후 미션별·연속 실행 결과는 별도 테스트 보고서에 기록한다.

## 연구와 공식 구현 자료

### 1. KISS-ICP — 공통 LiDAR 위치 추정

- 논문: Vizzo 외, **KISS-ICP: In Defense of Point-to-Point ICP — Simple, Accurate, and Robust Registration If Done the Right Way**, IEEE RA-L, 2023.
- 공식 자료: [저자 저장소와 논문 링크](https://github.com/PRBonn/kiss-icp), [ROS 2 wrapper](https://github.com/PRBonn/kiss-icp/blob/main/ros/README.md), [Python API](https://github.com/PRBonn/kiss-icp/blob/main/python/kiss_icp/kiss_icp.py).
- 활용: LiDAR 프레임을 정합해 센서의 상대 이동을 추정하고, 공개된 시뮬레이터 초기 자세와 로봇 링크 TF로 월드 좌표의 pelvis 위치를 계산한다. bringup의 추정기를 미션 사이에도 유지하고, 실제 현재 위치가 아닌 `selected` 응답으로 재초기화하지 않는다.
- 채택 이유: CPU에서 동작하며 Python 및 ROS 2 연동 경로가 있다. GPU 8GB를 시뮬레이터와 VLM에 사용할 수 있고, 보행 정책을 새로 학습하지 않고 공통 이동 기능을 연결하기에 적합하다고 판단했다.
- 한계: 단순한 실내 복도, 동적 팔다리, 보행 진동에서 정합이 퇴화하거나 드리프트할 수 있다. 첫 자세의 IMU 초기화와 센서 TF도 정확해야 한다. 이 대회 환경의 성능은 실제 실행 결과로 확인해야 한다.

### 2. FAST-LIVO2 — 향후 센서 융합 개선 후보

- 논문: Zheng 외, **FAST-LIVO2: Fast, Direct LiDAR-Inertial-Visual Odometry**, arXiv 최초 공개 2024-08-26, 확인한 개정본 2024-08-28.
- 공식 자료: [논문 원문](https://arxiv.org/abs/2408.14035), [저자 저장소](https://github.com/hku-mars/FAST-LIVO2).
- 내용: LiDAR·IMU·영상을 칼만 필터 안에서 융합하고, 직접 정합으로 위치를 추정한다.
- 이번 기본 구현에 바로 넣지 않은 이유: 센서 시간 동기화, 외부 파라미터, point cloud의 시간 필드와 메시지 형식 점검이 추가로 필요하다. 먼저 단순한 위치 추정의 실제 실패 양상을 확보한 뒤 개선 후보로 비교하는 편이 구현 시간을 관리하기 쉽다고 판단했다.

### 3. Visual Servo Control — 콘과 공의 폐루프 접근

- 자료: Chaumette·Hutchinson, **Visual Servo Control, Part I: Basic Approaches**, IEEE Robotics & Automation Magazine, 2006.
- 저자 공개 원문: [Visual Servo Control, Part I](https://www-cvr.ai.uiuc.edu/~seth/ResPages/pdfs/ChaHut06.pdf).
- 활용: 영상에서 물체 중심의 오차와 깊이 측정치를 반복 관측하면서 회전·전진 속도를 조절한다.
- 채택 이유: 미션 2의 색 콘과 미션 6의 공은 근거리에서 반복 관측할 수 있다. 고정 시간 동안 움직이는 방식보다 오차를 직접 줄이는 제어를 구성하기 쉽다. 논문의 일반 원리를 참고했으며, 논문의 전체 제어기나 성능을 재현했다고 주장하지 않는다.
- 한계: 색 분할, 가림, 깊이 결측, 카메라 기울기와 좌표 변환 오류에 영향을 받는다. 공을 골에 넣는 성공률은 접근 제어만으로 보장되지 않는다.

### 4. SmolVLM — 경량 실제 VLM 후보

- 공식 발표: **SmolVLM Grows Smaller — Introducing the 256M & 500M Models!**, 2025-01-23.
- 논문: **SmolVLM: Redefining small and efficient multimodal models**, 2025.
- 공식 자료: [개발팀 설명과 추론 예시](https://huggingface.co/blog/smolervlm), [500M 모델](https://huggingface.co/HuggingFaceTB/SmolVLM-500M-Instruct).
- 활용: 미션 4에서 카메라 영상의 실내 물체와 방의 용도를 해석하는 후보이다.
- 고려 이유: 256M·500M 크기의 모델과 공식 Transformers 추론 예시가 있어 GPU 메모리가 제한된 환경에서 우선 시험할 수 있다.
- 한계: 작은 파라미터 수가 방 분류 정확도를 보장하지 않는다. 실제 대회 렌더링 영상으로 확인해야 하며, 모델을 설치하지 않았거나 추론하지 않은 상태를 VLM 구현 완료로 간주하면 안 된다.

### 5. Qwen3-VL-2B — 방 인식 개선 후보

- 공식 2B 모델 공개: 2025-10-21. 기술 보고서: **Qwen3-VL Technical Report**, 2025.
- 공식 자료: [개발팀 저장소와 공개 이력](https://github.com/QwenLM/Qwen3-VL), [Qwen3-VL-2B-Instruct 모델](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct).
- 내용: 영상·텍스트 입력을 함께 처리하며 OCR, 물체 및 공간 이해를 지원한다.
- 고려 이유: 경량 모델의 분류가 불안정할 경우 비교할 수 있는 더 큰 VLM 후보이다. 방 세 곳의 관측을 모아 제한된 클래스 중 답하게 하는 실험을 구성할 수 있다.
- 한계: 가중치 외에도 이미지 토큰과 캐시가 메모리를 사용한다. RTX 5060 Laptop 8GB에서 시뮬레이터와 동시 실행할 수 있는지는 실제 메모리·지연 측정이 필요하다. GPU 적합성은 모델 크기에 근거한 예상일 뿐 실측 결과가 아니다.

### 6. TANGO — 최신 휴머노이드 탐색 연구와 범위 판단

- 논문: Li 외, **TANGO: Humanoid Navigation in Cluttered Environments with a Whole-Body Vision-Language-Action Model**, 2026-09-08 최초 공개, 확인한 개정본 2026-10-01.
- 원문: [arXiv 논문](https://arxiv.org/abs/2609.09158).
- 내용: 언어와 로봇 시점 RGB 관측으로부터 29DoF 전신 행동을 예측하고, 시뮬레이션 학습을 거쳐 Unitree G1에서 탐색하는 접근이다.
- 이번 기본 구현에 채택하지 않은 이유: 별도 행동 데이터 생성과 학습, 제어 인터페이스 전환이 필요하다. 제공 보행 정책 위에서 센서 기반 이동과 미션 인식을 연결하는 현재 목표에 비해 작업 범위가 크다. 논문의 성과를 이 대회 코드의 성과로 인용하지 않는다.

## 검증 해석

실제 성공 판정은 조교 원본 시뮬레이터와 referee가 남긴 결과를 따른다. 알고리즘 선택의 타당성과 미션 성공은 별개의 주장이다. 단일 기본 시나리오의 PASS를 일반적인 성공률로 표현하지 않고, 실패·시간 초과·모델 미설치·호출 오류를 그대로 보고한다. 마지막에는 초기 위치, 시나리오, 실행 명령, 커밋, 결과 파일을 함께 남겨 팀원이 재현할 수 있게 해야 한다.
