## Failure evidence and changes

The previous broader checks passed 12/17 attempts, with detection, stop-position,
and shared route/localization failures recorded in `ys_m2_checks_20261123.md`.
The first three targeted baseline reruns here all passed, confirming that the
failures are intermittent. They are retained rather than used to claim a clean
before/after improvement.

1. Allow the robot to settle for 0.8 seconds after stopping at a survey heading,
   then require fresh RGB/depth pairs. Increase the bounded survey from 1.5 to
   3 seconds, including settling. Target estimates in the earlier captured
   survey drifted after the turn, consistent with transient body motion.
   Settling is a targeted mitigation; these tests do not isolate every cause of
   the earlier stop error. The target offset remains unchanged:
   measured surface + 0.08m - 0.75m. No referee position is used by the controller.
2. A settling-only trial still missed a visibly blue cone. Its saved RGB-D frame
   contains 5,761 blue pixels, but the shared floor estimate gives them heights
   between roughly -1.78 and -1.32m (5th–95th percentiles). The old absolute-height
   gate removes them all. Mission 2 now overrides only cone detection: require a
   connected coloured component with plausible relative 3-D dimensions instead
   of requiring positive height above that fitted plane. The colour, finite
   depth, area, aspect ratio, public room bounds and multi-frame consensus gates
   remain. Flat coloured patches and oversized components are rejected.
3. Optional `HAIC_M2_CAPTURE_DIR` captures successful surveys too, allowing direct
   comparison with failed surveys. Captures are diagnostic only and not read by
   the controller. The final simulation batches run with capture disabled.

The failed blue frame now returns a measured surface near (16.9624, 24.7170).
This is a sensor replay result, not an official mission PASS. The settling-only
trial passed green and orange and failed blue; it is not the final candidate.

## Reproduction and limitations

On OMEN, activate `/home/aril/miniconda3/envs/haic_rai301_verify`, select the ys
worktree's `src`, prepend it to `PYTHONPATH`, and confirm the GPU is free. Run:

```bash
python -m unittest custom.mission_2.test_mission_2 -v
python -m unittest discover -s custom/tests -v
python custom/mission_2/evaluate.py --run --source-root "$PWD" --output /tmp/ys-m2-new-run
```

Each output directory must be new. For targeted repetitions, append
`--case order-1-green --case order-1-orange --case order-2-blue`.
The fresh-layout evaluation script and manifest are included beside this report;
adjust its source/output paths for a new checkout. This script is evaluation-only
and never imported by mission control.

Raw logs/captures remain on OMEN under `/tmp/ys-m2-*1123` and
`/tmp/ys-m2-*-captures`, and are copied under
`output/ys-missions/m2-fixes-20261123/` on the Mac. Large captures are excluded
from Git. Source hashes are retained with the official records; the remote
candidate worktree's base commit alone does not identify its uncommitted source.

These changes cannot fix shared route stalls or stale localization. Final target
projection and approach still depend on shared pose estimates. A passing finite
batch does not establish competition-wide reliability, and the 8cm surface
correction remains an inherited approximation rather than a calibrated radius.
