## Changes and hypotheses

- `mission_4.py`: wait for two new camera timestamps after alignment, decode padded RGB/BGR/RGBA/BGRA rows, and collect two actual views per room at headings -0.15/+0.15 rad. Observations and returned labels remain ordered north→middle→south. Optional HAIC_M4_CAPTURE_DIR saves the actual camera PNGs; the evaluator enables it.
- All long hallway movement goes through x=15.5, with intermediate points at most 2.5 m apart, before a short approach to x=16.7 at the published door y. The classroom return uses the same pattern and explicitly faces the doorway before entry at lower speed. This is a mission-specific waypoint change using the existing Navigator; it does not correct or replace shared localisation.
- `vlm.py`: one bounded CPU subprocess loads the real SmolVLM once for all six views. Preserve the baseline image-conditioned candidate log-likelihood calculation. Average scores of views from the same room, then use the public uniqueness condition to rank room assignments. API observations without scores must agree across the two views; conflicting labels are rejected.
- Reject score ties and assignments with margin at most 0.25. The threshold is provisional, not a calibrated confidence probability. Raw view scores, independent labels, assignment margin, camera stamps, estimated poses, model load/inference time and failure stage are returned as evidence. Correct room labels never conceal a failed delivery.
- A 240 s inference allowance is used inside the bounded 600 s mission attempt. Six views cost more computation than the baseline's three; batching removes repeated model loading but does not imply lower total latency.
