## Runtime changes

Both missions inherit the v2 public-sensor Mission adapter and explicitly
ignore begin_mission()'s None return value. Navigator uses the existing
continuous estimate, without mission-selection pose resets.

A public respawn immediately commands a stop. Nonzero commands are guarded
against an observed respawn, including commands issued by shared navigation.
Bounded observation/navigation phases reject an attempt spanning a respawn.
This is a conservative abort, **not automatic recovery or resurvey**.

Mission 2 clears invalidated cone measurements and settled-stop evidence. Its
fresh RGB-D pairing, detector, surface correction, speed, tolerances and
no-final-turn/0.5-second settle behavior are preserved. Its cone survey also
discards snapshots if a respawn occurs while gathering frames.

Mission 4 discards previous-layout room answers, views, assignment and crop
retry evidence after a respawn, including one during VLM inference or final
delivery. It returns restart_required instead of submitting stale labels.
The VLM worker remains bounded by its existing inference timeout; a respawn
does not currently cancel that CPU worker early, but its output is rejected
and robot motion stops through the public callback.

The default VLM remains local CPU SmolVLM with the previously tested scoring
and SDPA optimization. Loading is offline-only from installed files/cache.
The optional HTTP backend requires a loopback, RFC1918 LAN, Tailscale IPv4,
or IPv6 ULA literal address (localhost is normalized). Public endpoints,
redirects and environment proxies are rejected/disabled. Only the dedicated
HAIC_VLM_API_KEY is used, if set; OPENAI_API_KEY is never inherited.
The caller must establish that a private endpoint is actually team-owned.
No team server deployment or live HTTP inference is claimed.
